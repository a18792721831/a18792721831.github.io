## 介绍

MySQL主从复制是将来自一个MySQL数据库实例(Master)的数据复制到一个或者多个MySQL数据库实例(Slave)。

主从复制是MySQL的核心功能，使用主从复制可以完成MySQL的数据同步，备份，高可用，迁移等工作。

整个MySQL主从复制操作主要由3个线程完成。一个线程(dump线程)在Master节点上，SQL线程和 I/O线程在 Salve 节点上。

![image-20250307165146334](https://i-blog.csdnimg.cn/img_convert/e1298e94f4c9a2ce348095e5e7e6c415.png)

主从复制的过程大致如下：

  1. Slave节点执行 change master to 连接上 Master 节点，连接上Master 节点后，发送Binlog 的位点信息。
  2. Slave 节点的 I/O 线程和 Master 节点的 dump 线程建立连接。
  3. Slave 节点的 I/O 线程向 Master 节点发起 Binlog 的请求。
  4. Master 节点的 dump 线程根据 Slave 节点的请求，将本地 Binlog 以 events 的方式发送给 Slave 节点的 I/O 线程。
  5. Slave 节点的 SQL 线程应用 RelayLog ，并且把应用过的日志记录到 relay-log.info 中，在默认情况下，已经应用过的 RelayLog 会自动被清理掉。

尝试手动搭建一下主从复制

## 数据库准备

创建数据库需要挂载的目录

![image-20250307180302239](https://i-blog.csdnimg.cn/img_convert/f36abb0a1c64ddaffb94840a56a3028b.png)

创建mysql配置文件`my.cnf`

master
    
    
    [mysqld]
    server_id=100
    

slave
    
    
    [mysqld]
    server_id=101
    

> 需要保证 my.cnf 的文件权限是 644，权限过大，mysql会忽略配置文件

首先使用docker 启动两个mysql实例
    
    
    docker run \
    --name master \
    -e MYSQL_ROOT_PASSWORD=master \
    -v /data/mysql/master/log:/var/log/mysql \
    -v /data/mysql/master/data:/var/lib/mysql \
    -v /data/mysql/master/conf:/etc/mysql/conf.d \
    -p 3106:3306 \
    -d \
    mysql:8.0 
    
    
    
    docker run \
    --name slave \
    -e MYSQL_ROOT_PASSWORD=slave \
    -v /data/mysql/slave/log:/var/log/mysql \
    -v /data/mysql/slave/data:/var/lib/mysql \
    -v /data/mysql/slave/conf:/etc/mysql/conf.d \
    -p 3107:3306 \
    -d \
    mysql:8.0 
    

![image-20250307174511180](https://i-blog.csdnimg.cn/img_convert/be54aaa2ab9528d3df16665e923941d9.png)

## 开启 Binlog

增加目录

![image-20250308092110936](https://i-blog.csdnimg.cn/img_convert/834f324318db551e1484ed9fb68bcb8b.png)

在配置文件中配置binlog的目录

![image-20250308150342582](https://i-blog.csdnimg.cn/img_convert/982177691ca00f0ce6bf5251e13cc9ff.png)

修改启动命令
    
    
    docker run \
    --name master \
    -e MYSQL_ROOT_PASSWORD=master \
    -v /data/mysql/master/log:/var/log/mysql \
    -v /data/mysql/master/data:/var/lib/mysql \
    -v /data/mysql/master/conf:/etc/mysql/conf.d \
    -v /data/mysql/master/binlog:/var/lib/mysql-bin \
    -p 3106:3306 \
    -d \
    mysql:8.0 
    
    
    
    docker run \
    --name slave \
    -e MYSQL_ROOT_PASSWORD=slave \
    -v /data/mysql/slave/log:/var/log/mysql \
    -v /data/mysql/slave/data:/var/lib/mysql \
    -v /data/mysql/slave/conf:/etc/mysql/conf.d \
    -v /data/mysql/slave/binlog:/var/lib/mysql-bin \
    -p 3107:3306 \
    -d \
    mysql:8.0 
    

重启

> 记得使用 `chmod -R 777 ./*` 进行授权，否则会出现 Permission denied 的异常，导致docker 容器启动失败
> 
> my.cnf 必须是 644

## 创建主从复制的用户

在Master节点上创建用户，授予 `replication slave` 权限。
    
    
    -- 创建用户
    create user 'rep'@'%' identified by 'mspswd';
    -- 授权
    grant replication slave on *.* to 'rep'@'%';
    -- 刷新权限
    FLUSH PRIVILEGES;
    -- 验证
    SHOW GRANTS FOR 'rep'@'%';

![image-20250308155052413](https://i-blog.csdnimg.cn/img_convert/2fcd59b4911fb3bda8788c185bafae60.png)

查看同步状态

![image-20250308160056037](https://i-blog.csdnimg.cn/img_convert/a1a66ed678be5d4bb363efb701740650.png)

发现有报错，使用 replication user 连不上 master

![image-20250308140839448](https://i-blog.csdnimg.cn/img_convert/3e674103a3ed19786fac6e5d94fea2aa.png)

解决方案一：

在master执行：
    
    
    -- 修改复制用户的认证方式
    ALTER USER 'rep'@'%' 
    IDENTIFIED WITH mysql_native_password BY 'mspswd';
    -- 刷新权限
    FLUSH PRIVILEGES;
    

但是该方案不生效，因为在 8.0 中， mysql_native_password 是被禁用的

![image-20250308141943706](https://i-blog.csdnimg.cn/img_convert/044c31d6304b87337fd8fe6767680a78.png)

需要启用该插件，Master启用即可

启用插件：

首先修改配置文件（配置文件不生效是因为权限过大，必须是644）：

![image-20250308142211570](https://i-blog.csdnimg.cn/img_convert/93ce67ffe303aa0877847f57b10e0a7f.png)

使用
    
    
    SELECT plugin_name, plugin_status, plugin_type 
    FROM information_schema.plugins 
    WHERE plugin_name = 'mysql_native_password';
    

验证是否生效

![image-20250308160233386](https://i-blog.csdnimg.cn/img_convert/7ec3284c396ffed82db337291630342d.png)

Slave 节点执行 `start slave` 命令开启同步复制，并使用 `show slave status` 命令查看同步状态。

需要重点关注`Slave_IO_Running`和`Slave_SQL_Running`，其中 `Slave_IO_Running` 表示 Slave 节点是否能够正常从Master节点同步数据；`Slave_SQL_Running`表示回放RelayLog 文件中的 Binlog 时是否正常。

![image-20250308160717577](https://i-blog.csdnimg.cn/img_convert/881198bfc8f724250075fd16c74c46c3.png)

当`Slave_IO_Running=YES`和`Slave_SQL_Running=YES` 表示成功的建立了主从复制。
