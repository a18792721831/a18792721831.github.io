1.docker安装

yum install docker -y

1

1

docker run hello-world

touch Dockerfile

COPY /tomcat8.0.53 /$INNER_PATH/

RUN mkdir -p $INNER_PATH
#执行命令 mkdir -p 如果上级目录不存在，那么创建上级目录
RUN ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone
#设置时区
RUN yum install kde-l10n-Chinese -y
#下载中文包
RUN yum reinstall glibc-common -y
#下载中文插件

ENV LC_ALL zh_CN.GBK

#容器对外开放8080端口

#容器对外开发443端口

#必须执行的命令
CMD ["tail","-99f","/tomcat/logs/catalina.out"]

3.docker镜像的创建

1

docker build -f test/Dockerfile --tag=tomcat:test .

注意点：

  • 使用-f参数就需要指定dockerfile的位置；
  • 如果不指定dockerfile的位置，那么需要在dockerfile所在的位置执行，即需要把dockerfile从test文件夹中拿出来。
  • –tag参数表示的是 镜像名：版本
  • 不要忘记最后面还有一个点，这个点就是dockerfile的上下文环境，如果没有这个点，在复制文件的时候会找不到文件
  • 也可以不使用点而是 / 把根目录作为上下文环境，那么在dockerfile中拷贝文件的上下文就是根目录，这样dockerfile与真实环境的上下文一致了。


4.启动镜像

1

docker run -d -p 17001:8080 -p 17002:443 -v /StarFSA/fsa/develop-4.3.0/webapps:/tomcat/webapps --name=tomcat_test tomcat:test

命令说明：
docker run 启动docker 镜像
-d表示后台启动
-p表示端口映射将宿主机（真实的物理机器）的17001端口映射到容器的8080端口，访问宿主机的17001端口等价于访问容器的8080端口
-v文件挂载：将宿主机的目录挂载到容器的目录下。等效于dockerfile中的COPY，但是更加灵活，非常适合于经常变更的内容，比如tomcat的webapps目录
–name为这个容器起个别名
tomcat:test表示启动的容器使用的镜像

5.常用命令

  • docker镜像查看

    docker images

  • docker容器查看

    docker ps -a

  • docker实例查看

    docker ps

  • 没有指定容器的名字那么会随机生成。
    (个人理解)
  • 镜像第一次启动创建了容器，容器启动产生了实例，当实例停止运行就成为了容器。
  • 镜像定义了一个容器的环境
  • 容器是实例停止运行时的载体
  • 容器启动就是实例
  • 实例可以认为一个运行的真机
  • 容器是一个关机的机器
  • 镜像就是机器的配置

  • docker停止实例、启动容器

    docker start $id|$name docker start tom_zh


  • 与实例进行交互

    docker exec -it $id|$name /bin/bash docker exec -it tomcat_test /bin/bash


exit退出，在实例内可以认为在一个单独的机器内。

  • 查看实例的输出（日志）

    docker logs -f $id|$name docker logs -f tomcat_test

docker logs -f等价于tail -f
可以ctrl+c活着ctrl+z退出

  • 停止一个实例

    docker stop $id|$name docker stop tomcat_test

  • 对于tomcat_test这个容器，随时可以启动或者终止。

  • 删除容器

    docker ps -a docker rm $id|$name

  • 删除镜像

    docker images docker rmi $id|$name
