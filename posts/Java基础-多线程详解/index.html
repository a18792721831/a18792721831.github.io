1. 进程 线程 协程

1.1 操作系统类型

作业是用户在一次处理中要求计算机系统做的操作的集合。
目前操作系统基本上可以分为3类：

  1. 批处理操作系统
  • 用户提交作业给系统
  • 系统将若干作业分为一个批次加载入外存
  • 系统按一定的策略选择一个作业加载入内存执行
  • 作业运行完成或错误
  • 系统输出已执行的作业，并继续下一个作业

策略常见的有：先到先服务，优先级等。
优点：
减少人工干预，提交机器利用率。
缺点：
作业阻塞时，系统阻塞；无交互。

  1. 分时操作系统
  • 用户发出系统使用请求
  • 系统将用户请求放入时间分配范围内
  • 用户使用完成或分配用户的时间已到，暂停用户使用，分配下一用户
  1. 实时操作系统
    实时操作系统和分时操作系统相当类似，甚至其工作基本原理相似。区别在于，分时操作系统中，用户的请求可能需要很长时间才能执行完成（如果用户过多的话）；在实时操作系统中，不管用户数量是多少，操作系统必须在指定的时间内进行响应。
    如果分时操作系统的时间片分配的足够小，那么，其可以当做一个实时操作系统。

在现代操作系统中绝不是单独一个类型的操作系统，都是多种模式配合使用。

1.2 线程

线程是操作系统调度的最小单位。线程是一系列作业的组合。
线程是独立调度和分派的基本单位。线程可以为操作系统内核调度的内核线程。
线程的实体包含程序、数据和TCB。
线程是动态概念，线程的动态特性有线程控制块TCB(Thread Control Block)描述。

一个TCB包含以下信息：

  • 线程状态
  • 线程中断现场
  • 执行堆栈
  • 线程局部变量主存
  • 进程的主存和其他资源

线程还有一些其他的信息也需要被保存：
程序计数器，状态参数和返回地址等。

1.3 进程

进程是程序在操作系统中的一次运行活动。
进程是资源分配的基本单位。
进程是操作系统结构的基础。
进程是线程的容器。
程序由指令，数据和组织形式构成。
进程则是程序在运行环境下的一次运行活动。

狭义：进程是正在运行的程序的实例
广义：进程是一个具有一定独立的程序的关于数据集合的一次运行活动。
独立程序，表示程序其有静态的代码实现(二进制也是代码的一种体现)
数据集合，运行时环境。


进程的动态特性是PCB实现的。

1.4 线程和进程的关系

前面有提到，进程可以看做是线程的容器。不管是进程还是线程都有自己的数据区，代码区以及动态控制器。
线程可以访问线程所属的进程的资源，包含IO网络等资源。
线程或者进程都有自己的状态，数据以及堆栈。
线程依赖于进程。
进程间通信IPC，线程之间通信可以直接读写数据(需进行并发处理)
现代操作系统中，进程是资源调度的最小单位；线程是执行调度的最小单位。

因此，线程的上下文信息(状态，中断恢复，局部变量数据，程序调用堆栈等)远远小于进程的上下文信息。
所以，线程的上下文切换快于进程的上下文切换。

1.5 协程

相比于进程，线程的上下文信息已经很小了，但是往往有些切换，有效操作的时间小于线程上下文切换的时间。也就是说，线程的上下文切换，还是浪费资源。
在此基础上，提出了协程的概念，也叫微线程。
协程简化了线程的上下文组成，只保留了程序调用堆栈和局部变量数据以及返回地址等。
协程非常类似子程序调用过程。
目前协程直接支持的编程语言不多。

1.6 协程和线程的关系

协程是基于线程的，所以协程切换不用切换线程上下文。也就是说，协程的调度中需要的资源是及其小的，几乎可以忽略不计。
协程是线程自己调度的，可以根据业务进行调度。
协程不需要线程并发的锁机制，不存在并发写读等冲突。

1.7 并行&串行

并行与串行：

串行：
嘴巴和鼻子，在同一时刻，要么呼吸，要么喝水进食。
你永远无法做到，同时呼吸，同时喝水进食。会被呛到。
这就是串行，某一个时刻只能做一件事情。
因为呼吸与喝水进食，并用咽喉。不管是进食，还是呼吸，都需要经过咽喉。一个人只有一个咽喉，所以，同一时间只能做一件事情。

并行：
每个人都可以一边进食，一边听歌。
因为进食与听歌使用的是不同的器官，他们之间没有冲突。所以可以在同一时刻，做多件事情。

在计算机的世界中，计算机进行操作的单位是处理器核心。如果处理器只有一个核心，那么就是串行的，如果处理器有多个核心，那么可以串行可以并行。

请注意：并行和串行研究的是时刻。

1.8 并发&并行

在过去的一个小时内，我吃了蔬菜，吃了米饭，喝了水。
可以说，在这一个小时内，我并发吃了蔬菜，米饭以及喝水。
所以，并发研究的是时间段，并行研究的是时间点。

1.9 阻塞&非阻塞

阻塞是指当线程或进程在运行状态，因请求资源，长时间未得到资源，被操作系统挂起，改变了状态，切换了上下文。
非阻塞是指当线程或进程在运行状态，请求资源，在资源未得到响应期间，不会被操作系统挂起，不会修改状态，不会进行上下文切换。

1.10 同步&异步

同步：
进程请求资源，在资源响应期间，进程没有做任何事情，在等待资源响应。

异步：
进程请求资源，在资源响应期间，进程还做了其他的事情；资源响应后，继续执行请求资源后面的操作。

一般来说，同步是阻塞的，异步是非阻塞的。
异步一般性能优于同步。

    static class LiftOff implements Runnable{

        protected int countDown = 10;
        private static int taskCount = 0;
        private final int id = taskCount++;
        public LiftOff(){}
        public LiftOff(int countDown){
            this.countDown = countDown;
        }

        public String status(){
            return "#" + id + "(" +
                    (countDown > 0 ? countDown : "LiftOff!") + ").";
        }

        @Override
        public void run() {
            while (countDown-- >=0 ){
                System.out.println(status());
                Thread.yield();
            }
        }
    }

这个任务是：打印当前的线程信息，以及线程内的计数器。
每打印一次，就让出CPU执行权，等待下一次调度执行。

2.4 线程这样使用的问题

main线程创建了新的线程后，main线程没有捕获新创建的线程的任何引用。在使用普通对象时，这对于垃圾回收来说是一场公平的游戏，但是在使用Thread时，情况就不同了。每个Thread都注册了他自己：

因此，确实有一个对它的引用，而且，在它的任务退出run方法并死亡之前，垃圾回收器都无法清除。
线程不仅仅包含任务，还有线程自己的一些线程信息，所以，线程创建与回收都是一件浪费资源的事情。
那么，对于任务区别不大的任务，能不能用已有的线程驱动，避免线程的创建与回收？

调用Executors的newCachedThreadPool的方法创建了一个线程池，初始0个线程，最多Integer.MAX_VALUE个线程。

阿里编码规范中强制不允许使用此种方式创建线程。
调用了shutdown方法后，不在接受新的任务，而Executors线程将在所有子线程完成后尽快结束。

    static class RightOff implements Callable<String> {

        private int id;

        public RightOff(int id) {

ExecutorService service = new ThreadPoolExecutor(5, 10, 0L, TimeUnit.MILLISECONDS, new LinkedBlockingQueue<>());
        ArrayList<Future<String>> results = new ArrayList<>();
        for (int i = 0;i < 10;i++){
            results.add(service.submit(new RightOff(i)));
        }
        for(Future<String> future : results){
            try {
                System.out.println(future.isDone());
                System.out.println(future.get());
            } catch (ExecutionException e){
				System.out.println("ExecutionException");
                return;
            } catch (Exception e){
                e.printStackTrace();
                return;
            } finally {
                service.shutdown();
            }
        }

submit方法会产生Future对象，它用Callable返回结果的特定类型进行参数化。
可以调用isDone方法查询Future是否已经完成。
当任务完成时，具有返回结果，可以调用get方法获取结果。
也可以不用isDone方法判断是否完成，而是直接调用get方法获取结果。但是这种方法是阻塞的，程序main线程会一直阻塞在get方法，等待返回。为了防止长时间程序阻塞，可以调用带有超时时间的get方法。
使用带有超时时间的get方法，如果在指定时间内，子线程没有交出结果，就会进行快速失败，抛出TimeOutException异常。

5. 线程状态(生命周期)

通过查看Thread内部类，我们可以知道，线程总共有5个状态。

有些资料，将TIME_WAITING和WAITING放在了一起。
在Java中则是分开的。

其中WAITING和TIME_WAITING都是BLOCKED状态

5.1 NEW

当程序使用 new 关键字创建了一个线程之后，该线程就处于新建状态，此时仅由 JVM 为其分配
内存，并初始化其成员变量的值。

5.2 RUNNABLE

当线程对象调用了 start()方法之后，该线程处于就绪状态。Java 虚拟机会为其创建方法调用栈和
程序计数器，等待调度运行。

5.3 RUNNING

如果处于就绪状态的线程获得了 CPU，开始执行 run()方法的线程执行体，则该线程处于运行状
态。

5.4 BLOCKED

阻塞状态是指线程因为某种原因放弃了 cpu 使用权，也即让出了 cpu timeslice，暂时停止运行。
直到线程进入可运行(runnable)状态，才有机会再次获得 cpu timeslice 转到运行(running)状
态。阻塞的情况分三种：

  • 等待阻塞：
    RUNNING状态执行了wait方法，JVM会把线程放入等待队列(waiting queue)中。
  • 同步阻塞：
    RUNNING状态的线程在获取对象的同步锁时，若该同步锁被别的线程占用，则JVM会把该线程放入锁池（Lock Pool）中。
  • 其他阻塞：
    RUNNINNGN状态的线程执行Thread.sleep或者Thread.join方法，或者发出资源请求时，JVM会把该线程设置为阻塞状态。当sleep状态超时，hoin等待线程终止或者超时，以及资源请求被响应时，线程重新进入RUNNABLE状态。

5.5 DEAD(TERMINATED)

线程死亡都是通过以下三种方式的。线程结束后，就是线程死亡状态了。

  • 正常结束：
    run或者call方法执行完成，线程正常结束。
  • 异常结束：
    线程抛出一个未捕获的Exception或者Error.
  • 调用stop：
    直接调用线程的stop方法结束线程(这种方式不安全，容易造成死锁)

6.4 stop方法终止线程

程序中可以直接使用 thread.stop()来强行终止线程，但是 stop 方法是很危险的，就象突然关
闭计算机电源，而不是按正常程序关机一样，可能会产生不可预料的结果，不安全主要是：
thread.stop()调用之后，创建子线程的线程就会抛出 ThreadDeatherror 的错误，并且会释放子
线程所持有的所有锁。一般任何进行加锁的代码块，都是为了保护数据的一致性，如果在调用
thread.stop()后导致了该线程所持有的所有锁的突然释放(不可控制)，那么被保护数据就有可能呈
现不一致性，其他线程在使用这些被破坏的数据时，有可能导致一些很奇怪的应用程序错误。因
此，并不推荐使用 stop 方法来终止线程。

7. sleep,wait,yield,join

  • sleep
    sleep()方法需要指定等待的时间，它可以让当前正在执行的线程在指定的时间内暂停执行，进入阻塞状态，该方法既可以让其他同优先级或者高优先级的线程得到执行的机会，也可以让低优先级的线程得到执行机会。但是sleep()方法不会释放“锁标志”，也就是说如果有synchronized同步块，其他线程仍然不能访问共享数据。
  • wait
    wait()方法需要和notify()及notifyAll()两个方法一起介绍，这三个方法用于协调多个线程对共享数据的存取，所以必须在synchronized语句块内使用，也就是说，调用wait()，notify()和notifyAll()的任务在调用这些方法前必须拥有对象的锁。注意，它们都是Object类的方法，而不是Thread类的方法。
    wait()方法与sleep()方法的不同之处在于，wait()方法会释放对象的“锁标志”。当调用某一对象的wait()方法后，会使当前线程暂停执行，并将当前线程放入对象等待池中，直到调用了notify()方法后，将从对象等待池中移出任意一个线程并放入锁标志等待池中，只有锁标志等待池中的线程可以获取锁标志，它们随时准备争夺锁的拥有权。当调用了某个对象的notifyAll()方法，会将对象等待池中的所有线程都移动到该对象的锁标志等待池。
    除了使用notify()和notifyAll()方法，还可以使用带毫秒参数的wait(long timeout)方法，效果是在延迟timeout毫秒后，被暂停的线程将被恢复到锁标志等待池。
  • yield
    yield()方法和sleep()方法类似，也不会释放“锁标志”，区别在于，它没有参数，即yield()方法只是使当前线程重新回到可执行状态，所以执行yield()的线程有可能在进入到可执行状态后马上又被执行，另外yield()方法只能使同优先级或者高优先级的线程得到执行机会，这也和sleep()方法不同。
  • join
    join()方法会使当前线程等待调用join()方法的线程结束后才能继续执行。

8. start与run

  • start
    用start方法来启动线程，真正实现了多线程运行，这时无需等待run方法体代码执行完毕而直接继续执行下面的代码。通过调用Thread类的start()方法来启动一个线程，这时此线程处于就绪（可运行）状态，并没有运行，一旦得到cpu时间片，就开始执行run()方法，这里方法 run()称为线程体，它包含了要执行的这个线程的内容，Run方法运行结束，此线程随即终止。
  • run
    run()方法只是类的一个普通方法而已，如果直接调用Run方法，程序中依然只有主线程这一个线程，其程序执行路径还是只有一条，还是要顺序执行，还是要等待run方法体执行完毕后才可继续执行下面的代码，这样就没有达到写线程的目的。

总结：调用start方法方可启动线程，而run方法只是thread的一个普通方法调用，还是在主线程里执行。这两个方法应该都比较熟悉，把需要并行处理的代码放在run()方法中，start()方法启动线程将自动调用 run()方法，这是由jvm的内存机制规定的。并且run()方法必须是public访问权限，返回值类型为void。

9. daemon

9.1 什么是daemon进程

指在程序运行的时候在后台提供一种通用服务的线程，并且这种线程并不属于程序中不可或缺的部分。
当程序中全部是后台进程时，后台进程将自动终止，同时系统也结束了。

9.2 优先级

daemon进程的优先级比较低，用于为系统中的其他对象和线程提供服务。
